## Implementation and acceptance boundaries

`motion-preference.ts` owns a single non-sensitive `cluster-reduce-motion` localStorage value. It reacts to OS and cross-tab preference changes; session-storage events do not alter it. Corrupt values default to following the OS. Storage denial leaves a usable in-memory choice with explicit unsaved copy. The preference deliberately remains local to this browser across accounts; no identity/campaign data is stored. The root layout owns subscription/listener cleanup and a document reduction attribute.

`GameMenu` uses native modal dialog containment/cancellation with an explicit close action and opener focus restoration. `PresentationSettings` is shared by that production menu in the galaxy, gallery and animation lab. The active game remains mounted underneath. Existing shared feedback cancels in-flight motion when reduction becomes active without replaying an acknowledged event when it is disabled. OS preference is also checked at action initialization, before layout mounting completes. Explicit animation-lab inspection still displays its paused requested comparison frame; it does not force playback against OS reduction.

Global reduced presentation removes CSS animation/transition/smooth-scroll effects. No renderer geometry, camera target, fleet position, clock, private view, action or outcome changes. Scene already renders on demand with damping disabled and immediate moves. This slice does not implement or claim low-detail texture/particle budgeting, contrast themes, audio, notifications, full rules navigation or complete UX15.
