# Selected conversation history

An invitation names its recipient and history scope. Future-only access remains the default. The creator can instead select specific earlier messages from the authorized conversation archive. The invitee reviews the scope and message metadata before accepting; acceptance grants exactly those messages plus future messages. Unselected earlier messages remain private.

The server resolves message references against immutable canonical history in the current encryption epoch. Client-supplied bodies are never trusted. Each reference must identify the same room and a message the inviter was authorized to receive. Wrong-room, unavailable, duplicate or mismatched references fail without admitting a recipient. The invitation carries the resolved selection so later messages cannot silently change its scope. Acceptance publishes a recipient-specific sharing event through the existing encrypted history and receipt machinery.

New campaigns record a sharing capability. Existing future-only campaigns keep their recorded behavior and explain the supported scope. The creator-only admission policy and limit of eight selected messages per invitation are development implementation choices under review, not new owner approval of game rules. The state budget still bounds publication; no unlimited archive is copied into active state.

The latest sharing event stays in active room state; immutable recipient history preserves every accepted disclosure. Removing or leaving ends future access without erasing knowledge already received. Rejoining with a future-only invitation does not grant additional absence-period messages. Provider migration preserves all authorized recipient histories and source references.

This slice adds no alliance, military permission or resource transfer. Its production invitation review, selected-history receipt, gallery and motion lab use the same projection and component paths. Implementation, tests and rendered evidence are in progress; hosted, CI and independent acceptance remain gates.

The selected invitation carries a unique consent token. Acceptance from an older future-only client fails without admission or disclosure. Failed references leave the campaign revision unchanged. Once accepted, an explicit sharing event preserves the original author/message identity and the grant time; deduplication does not invent a second message. Read state covers the selected history without granting unseen bodies.
