# Authorized campaign history

This slice connects the galaxy's History control to retained, encrypted member records. The bounded tray shows the roster, own credits and layer-entitled holdings as they appeared in each record. It does not infer events or dates that the service did not record. Opening history does not move the camera, change the selected system or submit a command.

The reader gets a current recipient key from the authoritative callable, then queries only that member's current-epoch history through Firestore access rules. Each page requests eleven records, displays ten and retains an epoch-bound descending cursor. Incoming records leave the loaded list intact; New records available explicitly loads the latest page. Envelope/grant binding, document identity and decrypted campaign/revision/epoch must agree. Failed pages do not append partial results. Closing or superseding a request discards its late response.

The phone tray owns the central task with a bounded scroll region and a persistent, safe-area-aware Return to galaxy control. Keyboard Escape restores the History control; recovery restores focus after a pending control becomes enabled. Network retry preserves loaded records. An epoch change requires Latest records instead of silently combining epochs. Account/member revocation continues to remove the live campaign through its existing subscriptions and denies new history reads; information already disclosed cannot be erased.

The gallery renders this production component in ready, pending and error states. The animation lab exposes its actual feedback motion through seek, replay, speed and reduced-motion comparison. There are no new art assets or alternate mock UI implementations.

## Evidence and scope

Type checking and lint pass. The existing fourteen unit tests pass (251 assertions). Two targeted service tests pass with 160 assertions using the mock provider and real AES-GCM with live Cloud KMS. They cross the ten-record boundary, hold the cursor stable after a later command, reject substituted envelopes/grants, deny wrong-reader and former-member access, and compare the complete previously authorized record set after real-to-mock epoch migration. This is emulator/live-key evidence, not hosted authentication certification.

The browser journey uses ordinary identity, create, join and pause/resume controls to produce retained records. A second tab commits a new record while the first reads earlier history. It checks bounded scrolling, persistent return control before automatic scrolling, no document overflow, reload, retry, stable reading position, selected-system preservation and keyboard restoration at phone, desktop, short desktop and 4K. Nine history/gallery/lab browser journeys pass in 35.2 seconds. Initial runs caught an ambiguous historical-name selector and loss of focus when a pending button disabled; both were corrected before final evidence. The final four-size focus-loop cohort passes in 28.9 seconds and includes the keyboard-scrollable history region in the dialog trap. Retained captures are in docs/ux/reviews/history; the implementer inspected phone and short compositions. Independent rendered review remains pending.

This is authorized snapshot browsing, not completion of patch compaction/replay, event-oriented absence briefings, production ticks, research or combat reports. Public rules remain under review. Hosted Google login, complete provider/key lifecycle, full CI and independent rendered/security acceptance remain separate gates. Existing server storage, grants and rules serve this slice; it introduces no backend deployment or plaintext history endpoint.
